# Epic 3 Context: Find and open a post (P1)

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

The family browses what they are subscribed to and opens a post: Главная shows the «Новое в подписках» feed, Подписки shows the author grid, an Author page lists one creator's posts, and the Post screen shows the post's text, one row per video, and honest locked-content copy, without ever crashing on unknown or malformed data. This is the second half of the P1 vertical slice (sign in → feed → post → video → resume); Epic 4 attaches the player to the media rows built here. Epic 2 was accepted on 2026-10-26. Story 3.1 (feed) and the feed refresh-on-resume change are done and device-accepted; Story 3.2 is in progress. **Where the newer long-term docs (`docs/api-contract.md`, `docs/focus-map.md`, `docs/testing.md`, ADRs 0007–0011, EXPERIENCE.md) or owner decisions contradict the epics/spine text, the newer source wins**; the overrides are called out below.

## Requirements & Constraints

- **Endpoints (no others):** feed E5 `GET /v1/feed/post/` (`limit=10`) → `{data{posts[], blogs, counters}, extra{offset, isLast}}`; author posts E4 `GET /v1/blog/{blogUrl}/post/` (`limit=20`) → `{data: Post[], extra{offset, isLast}}`; author header E3 `GET /v1/blog/{blogUrl}` → `title`, `blogUrl`, `owner{name, avatarUrl}` (no description/cover); subscriptions E2 `GET /v1/user/subscriptions?limit=30&with_follow=true` → `{offset, limit, total, data[].blog{title, blogUrl, owner{name, avatarUrl?}}}`, do not page (beyond 30 unverified); post E8 `GET /v1/blog/{blogUrl}/post/{postId}` → Post at top level. Every content call sends `comments_limit=0&reply_limit=0`.
- **Pagination:** `extra.offset` is opaque, passed back verbatim (URL-encoded); stop on `isLast`, a missing `extra`/`offset`, or an already-used cursor (cycle guard). Merge = append + dedupe by `post.id` (first kept). A page that adds nothing but has a next cursor auto-fetches, capped at 3 in a row. Merge tests use synthetic cursors.
- **Comments excluded everywhere:** ignore `count.comments` and `comments`; no counter, focus stop or request.
- **Entitlement:** locked = HTTP 200 with `hasAccess=false` (missing → true) or empty `data`; a `teaser`; empty `signedQuery`; never 403. Never show price, payment or subscribe action; the level name only if present (`subscriptionLevel` optional).
- **Invalid token looks anonymous:** E8 (inferred E4/E5) with a bad token returns 200 all-locked, not 401. Always attach the token; never treat a locked response as a session problem.
- **Verified errors:** missing post = E8 404 `{error: "not_found"}` → «Пост недоступен» + «Назад», no «Повторить». Missing blog = E3 404 `{error: "blog_not_found"}`. Unobserved 4xx → generic non-retried error; never treat 403 as expiry.
- **Defensive parsing:** drop and log (post id only) a post missing `id`, `createdAt`, `int_id`, `user.name` or `user.blogUrl` (the last is needed for routes/keys); never fail the page. Unknown blocks → `Block.Unknown`. A live `list` block (`items[]{data, items}`) renders nested text or the placeholder. Skip empty `playerUrls[].url`.
- **Media facts:** `ok_video.duration` (s) is in E4/E5 items; media identity = `ok_video.id`. `playerUrls`/`signedQuery` are signed, 24 h, personal: never logged, persisted, keyed, routed or in fixtures.
- **Content profile (ADR 0008):** LIVE for E8 and E5 (Story 3.1 device run). **E2, E3, E4 still unverified:** 3.2 checks E2, 3.3 checks E3/E4 on the device and records it in `docs/api-contract.md` §1; on rejection that endpoint moves to the auth header set minus `X-From-Id` with an ADR amendment, and the story asks the owner.
- **Performance baseline (pinned device):** median frame 31–32 ms is the device norm (the Google TV launcher shows the same); feed after fixes ≈ 9 % janky. Native view creation dominates page-mount cost (≈ 1.8 ms per `Text`), so keep card trees flat (PostCard has a «native view budget» test). New long lists must be judged on the device in a release-like build.
- **Verification:** Chromecast with Google TV 4K, release-like build `-PreactNativeArchitectures=armeabi-v7a`; label adb vs physical remote; mocks are never device results. Full suite ≥ 3 runs, new/changed focus/flow tests ≥ 30 runs before review; PRs only after review fixes. Still unverified on the device: TalkBack labels on cards, second-account cache isolation.

## Technical Decisions

- **HTTP client from the active session:** `src/app/session.ts` exports the one `session` (real or demo); repositories receive `session.http` via props (Shell → feature → hook → repository). `shared/api` has no singletons and must not regain them (demo would hit the real API). Images and non-`api.boosty.to` hosts get no Boosty headers.
- **Layers (AD-1):** screens use only hooks, `shared/ui`, `shared/focus`; only repositories call API clients. Post/Author/Media come only from `shared/entities` repositories, one Zod 4 schema per DTO (`shared/api/dto`), one mapper per entity. The Post entity exists (`src/shared/entities/post`: `PostRepository.feedPage`, `mergePosts`, `Block` union incl. `Unknown`); reuse and extend it (E4/E8), never copy it. Cross-feature navigation via typed id-only routes in `app/routes.ts` (`Post {blogUrl, postId}`, `Author {blogUrl}`).
- **Server state (ADR 0010):** `@tanstack/react-query` **5.104.2** installed. Keys only from `shared/api/queryKeys.ts` (no account id, URL, signed value or cursor; `QUERY_STALE_TIME_MS` lives there). `staleTime` 60 s, `gcTime` 10 min, no focus/reconnect refetch, no `focusManager`/`onlineManager`/NetInfo. Query-level `retry: false` (HttpClient owns AD-6 retries); «Повторить»/«Обновить» call `refetch`/`fetchNextPage`. Infinite lists use `refetchOnMount: false` (a refetch reloads every loaded page). The cache is account-scoped (AccountScope: cancel, then clear) and is also reset on every successful sign-in. A failed first-page retry keeps reporting the previous error so the StateView stays.
- **Refresh on resume (owner decision):** after a resume E1 `ok`, `refreshFeedHead` sends one E5 page 1 when the cached feed is ≥ 60 s old and collapses it into the cached first page (fresh copies win; page count, params, scroll and the focused card kept; a gap replaces the cache). Not a query invalidation. Open remainder: an anonymous E5 page fetched alongside a cold-start E1 that then refreshes the token is not invalidated.
- **Identity (AD-9):** keys are `post.id`, `blogUrl`, media `id`; a playable item is `MediaRef {blogUrl, postId, mediaId}`. Domain types expose no raw DTO fields, no `timeCode`, no signed URLs (progress only via Epic 4's ProgressRepository).
- **Lists (ADR 0011, overrides "FlatList with `getItemLayout`"):** `@shopify/flash-list` **2.3.3** exact. Grids are lists of rows of 3 keyed by the row's first item id (one item type, fixed row height), cards keyed by column inside a row. Hold back a trailing partial row while more pages may come; an end focus guide under the last row targets the focused card. `drawDistance` 3 rows, recycle pool 6, `removeClippedSubviews={false}`, explicit bounded viewport height. Recycled cells must reset per-item state: `useItemState(initial, itemKey)` and `FocusableSurface` `resetKey`; images keyed by URL. List images use `resizeMethod="resize"` and `fadeDuration={0}` (Graphics 325 → 37 MB). Focus room comes from slot padding (11) for Android's native focus scroll; never a JS scroll on focus. A data-change focus fix must key off D-pad events, never frame timing. Rollback to FlatList is documented in the ADR.
- **Shared pieces to reuse:** `PostCard` (+ skeleton, memoized), `src/test/feedFixtures.ts`, `useItemState`, `FocusableSurface`, the flow-test harness `src/test/flow.tsx` + `src/test/backHandlerMock.ts` (Epic 2 retro item 4; new tests must use it), `FixtureTransport` (the only HTTP mock), sanitized live fixtures in `src/test/fixtures/boosty/` (`npm run check:fixtures`).
- **Navigation (ADR 0007 overrides "native-stack"):** Author and Post are `@react-navigation/stack` screens in the shared screen wrapper with all-direction focus traps; Shell sections swap in place.
- **Phase gating (AD-20):** enable `subs` in `app/phaseFlags.ts` for 3.2; no «Смотреть» before Epic 4. Search, filters, «Обновить» button, «Мой блог» and the live card stay off.
- **SessionManager (Epic 2 retro item 5, ADR 0009 accepted):** the split runs between Epic 3 and Epic 4, right before Story 4.2. Epic 3 must not add session concerns to `sessionManager.ts`; any such need goes to the owner first.

## UX & Interaction Patterns

- **Grids are 3 columns** (owner decision 2026-10-26; overrides the 4-column feed and Author grid in the epics/design). PostCard width 221 = (720 − 2 × 12 headroom − 2 × 16 gap) / 3.
- **Главная (done):** skeleton keeps focus on `nav/home`; first cards take focus only if the user has not moved; refetch/pagination/images never move focus; inline «Повторить» on load-more failure; return to Главная keeps scroll and the remembered card (focus stays on the sidebar, → lands on it). OK on a feed card is not wired until 3.4. Ids `home/feed/<postId>`, `home/feed/retry`, `state/home/action`.
- **PostCard:** 16:9 preview, type badge (Видео, N видео, Аудио, Текст и фото, Опрос, Файл, Нет доступа), 2-line title (fallback: first text, then «Без названия»), avatar · author · date («сегодня, 14:30» / «вчера» / «12 окт» / «12 окт 2025»), duration only for a single-video post with a known duration. Locked: dimmed, lock glyph, «Нет доступа». No comment count. Deferred: a no-preview card should show the author avatar on a plate (3.6 or Epic 6).
- **Подписки:** AuthorCard (avatar, title, owner name), initial focus on the first tile, ids `subs/tile/<blogUrl>`. Empty: «Подписок пока нет» + explanation, no CTA, focus stays on the sidebar. «Показаны первые {n}» (resolved in 3.2): shown only when E2 returned the full 30 and `total > 30` (live `total` ≠ `data.length`: 5 vs 3, meaning unverified); not focusable.
- **Автор:** header (avatar, title, owner name) + post grid with PostCard, initial focus on the first post (no live card yet), ids `author/<blogUrl>/post/<postId>`. Empty: «Публикаций нет». Back pops to the origin.
- **Пост:** two independently scrolling columns. Left: author (OK → Author), title (≤ 6 lines), date, non-focusable like count. Right: text as plain paragraphs (styles/emoji in Epic 6); image, link, file, external video, audio, poll and unknown blocks as neutral non-focusable placeholders. Block ids `post/<postId>/block/<blockKey>` (`<type>:<id>`, else `<type>@<index>`).
- **MediaRow:** thumbnail, «Видео N», title, status; id `post/<postId>/video/<videoId>`; focusable for reading, no «Смотреть» while the player flag is off. Initial focus without the player is unspecified (focus-map assumes the primary button); locked post → the author.
- **Locked copy:** «Нет доступа. Этот пост доступен подписчикам уровня «…». Оформить подписку можно на сайте или в приложении Boosty.» No price, no button; teaser shown.
- **Restoration:** save `{focusId, scrollOffset}` in FocusRestoration before navigating forward; on return restore scroll, scroll the item into view by its current index (FlashList adapter), focus it once mounted. Fallback: neighbor by index → first item → action above. Refetch, pagination and image loading never move focus; Android post-pop fallback focus is never relied on. Every focusable element has a Russian accessibility label (e.g. «Видео. {title}. {author}, {date}.») from the `ru` catalog; tokens only from `shared/ui/tokens.ts`.
