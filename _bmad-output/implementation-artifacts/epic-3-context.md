# Epic 3 Context: Find and open a post (P1)

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

The family browses what they are subscribed to and opens a post: Главная replaces its placeholder with the «Новое в подписках» feed, Подписки shows the author grid, an Author page lists one creator's posts, and the Post screen shows the post's text, one row per video, and honest locked-content copy, without ever crashing on unknown or malformed data. This is the second half of the P1 vertical slice (sign in → feed → post → video → resume); Epic 4 attaches the player to the media rows built here. It also brings the first production content requests, TanStack Query and the shared entity layer. Epic 2 was accepted on 2026-10-26 (retro items 1–3 landed in PR #21). **Where the newer long-term docs (`docs/api-contract.md`, `docs/focus-map.md`, `docs/testing.md`, ADRs 0007–0008, EXPERIENCE.md) contradict the epics/spine text, the newer docs win**; the overrides are called out below.

## Requirements & Constraints

- **Feed (E5 `GET /v1/feed/post/`):** `limit=10`, `comments_limit=0`, `reply_limit=0`; response `{data{posts[], blogs, counters}, extra{offset: string, isLast}}`. **Author posts (E4 `GET /v1/blog/{blogUrl}/post/`):** `limit=20`, same comment params; response `{data: Post[], extra{offset, isLast}}`. **Author header (E3 `GET /v1/blog/{blogUrl}`):** `title`, `blogUrl`, `owner{name, avatarUrl}`; no description or cover. **Subscriptions (E2 `GET /v1/user/subscriptions`):** `limit=30`, `with_follow=true`; top-level `{offset, limit, total, data[]}` with `data[].blog{title, blogUrl, owner{name, avatarUrl?}}`; paging beyond 30 is unverified, so do not page. **Post (E8 `GET /v1/blog/{blogUrl}/post/{postId}`):** `comments_limit=0&reply_limit=0`, Post at top level (no `data` wrapper). No other endpoints.
- **Pagination:** `extra.offset` is an opaque string, passed back verbatim (URL-encoded); stop on `isLast == true` or a missing `extra`/`offset`. Merge = append, then dedupe by `post.id`, keeping the first occurrence. The cursor format was never recorded: merge tests use synthetic cursors. Cursor stability while new posts arrive is unverified.
- **Comments are excluded everywhere:** always send `comments_limit=0`/`reply_limit=0`; ignore `count.comments` and the post `comments` field; no counter, no focus stop, no comment request.
- **Entitlement:** a locked post is HTTP 200 with `hasAccess=false`, empty `data`, a `teaser` (image block), and an empty `signedQuery`; never a 403. A missing `hasAccess` defaults to true. Treat empty `data` as locked too. Never show a price, payment or subscribe action; the level name only if the post carries one (`subscriptionLevel` is present only as a key in live posts, so parse it optionally).
- **Invalid token looks anonymous:** E8 (and, inferred, E4/E5) with a bad or missing Bearer returns 200 with `hasAccess=false`, not 401. The session is validated by E1 at start and resume (Epic 2); content code must always attach the token and must not treat a locked response as a session problem.
- **Verified error signals:** missing post = E8 HTTP 404 `{error: "not_found"}` → «Пост недоступен» + «Назад», no «Повторить». Missing blog = E3 404 `{error: "blog_not_found"}`. 403/410/429/5xx on content were never observed: map unobserved 4xx to a generic non-retried error; never treat 403 as session expiry.
- **Defensive parsing:** drop (and log) a post missing `id`, `createdAt`, `int_id` or `user.name`; never fail the page. Unknown block types → `Block.Unknown` placeholder. A live `list` block exists (`items[]{data: ContentBlock[], items[]}`): render nested text or fall back to the placeholder. Empty `playerUrls[].url` entries are skipped.
- **Media facts:** `ok_video.duration` (seconds) and `timeCode` are already in E4/E5 items, so card durations come from the feed. Media identity is `ok_video.id`, never a URL. `playerUrls` and `signedQuery` are signed, 24 h, and account-scoped personal data: never logged, persisted, used as keys, put in routes or fixtures.
- **Content request profile is unproven for E2/E3/E4/E5 (ADR 0008):** they were verified only with the web header set. The first story that sends each (3.1 feed, 3.2 subscriptions, 3.3 blog/posts) checks it on the device and records the result in `docs/api-contract.md`; on rejection that endpoint moves to the auth header set minus `X-From-Id`, with an ADR amendment.
- **Performance:** the feed must stay smooth with hundreds of items. Per the deferred device note, **measure D-pad latency on the feed in a release build on the pinned device** before calling it acceptable (only the debug 300-item list was observed to lag).
- **Verification:** every P1 requirement on the Chromecast with Google TV 4K (build `-PreactNativeArchitectures=armeabi-v7a`); label adb-injected vs physical-remote results; mocks are never device results. Run the full suite ≥3 times and new focus/timer test files ≥30 times before review; open PRs only after review fixes.

## Technical Decisions

- **Get the HTTP client from the active session, never a singleton:** `src/app/session.ts` exports the one `session` (real or demo); repositories receive `session.http` through props/provider. `shared/api` no longer exports app singletons (retro items 1–2), and must not regain them, or demo mode would hit the real API.
- **Content profile (`HttpClient`):** mobile Android Chrome UA, `Accept`, `Authorization: Bearer`; no web headers. Images and any non-`api.boosty.to` host get no Boosty headers and never `Authorization`.
- **Layers (AD-1):** screens use only hooks, `shared/ui`, `shared/focus`, `shared/filters`; only repositories call API clients. Post, Author and Media are fetched only via `shared/entities` repositories with exactly one Zod 4 schema per DTO (`shared/api/dto`) and one mapper per entity; features add hooks, never their own copies of these calls. Cross-feature navigation only via typed id-only routes in `app/routes.ts` (`Post {blogUrl, postId}`, `Author {blogUrl}`).
- **Server state (AD-7):** TanStack Query only — not yet a dependency, so the first story adds it with a verified compatible pinned version. Keys only from `shared/api/queryKeys.ts`; lists via `useInfiniteQuery` with the opaque offset; `staleTime` 60 s, `gcTime` 10 min, no focus-based refetch; resume invalidates the visible list silently. The query cache is account-scoped: register it with `AccountScope` in `app/bootstrap.ts` so sign-out/account switch clear it.
- **Identity (AD-9):** keys are `post.id`, `blogUrl` and media `id`; a playable item is `MediaRef {blogUrl, postId, mediaId}`. Domain types expose no raw DTO fields and **no `timeCode`** (progress is read only through Epic 4's ProgressRepository).
- **Phase gating (AD-20):** enable `subs` in `app/phaseFlags.ts` for 3.2; gate any player entry point so no «Смотреть» dead-end appears before Epic 4. Search, filters, «Обновить», «Мой блог» and the live card stay off (Epic 5/7).
- **Lists:** `FlatList` with `getItemLayout`, stable id keys, React Native `Image`. Device lesson (Story 2.4): a list needs an explicit, bounded viewport height (`flex: 1` measured 0 on a pushed screen) and headroom so a focused card's ring does not cross the safe area.
- **Navigation (ADR 0007 overrides "native-stack" in the epics/spine):** Author and Post are `@react-navigation/stack` screens (no native screens), each in the shared screen wrapper with all-direction focus traps; Shell sections swap in place.
- **Fixtures:** sanitized live shapes exist in `src/test/fixtures/boosty/` (E2, E3 + missing, E4 ×2, E5, E8 accessible/locked/missing/no-token); `npm run check:fixtures` guards them. Long-list fixtures (300+ posts, 55 authors) are generated from these shapes. `FixtureTransport` is the only HTTP mock.
- **Epic 2 retro, before Story 3.1:** (item 4) the shared flow-test harness landed before 3.1 as a separate change: `src/test/flow.tsx` (settle profiles, render, queries, remote input, keychain, FixtureTransport and native-module setup) and `src/test/backHandlerMock.ts`. The 8 flow-test files and `ModalHost.test.tsx` were migrated, and new tests must reuse it. (item 5) the `SessionManager` split plan (restore/marker, sign-in, lifecycle/E1) runs as its own change before Story 3.1 (owner choice 2026-10-26, see `deferred-work.md`).

## UX & Interaction Patterns

- **Главная:** a 4-column feed grid of PostCards; ← from the first column → sidebar (`nav/home`). While the skeleton shows, focus stays on the sidebar; when the first card loads, focus moves to it **only if the user has not moved focus meanwhile** (focus-map refines the epic's "focus stays on the sidebar"). Load-more failure → inline «Повторить» (`home/feed/retry`) at the grid's end; OK reloads only that page, success focuses the first new card. Empty/full error → StateView with one action. Focus ids `home/feed/<postId>`.
- **PostCard:** preview, type badge (Видео, N видео, Аудио, Текст и фото, Опрос, Файл, Нет доступа), 2-line ellipsized title, author · date, duration only when provided. Locked: dimmed, lock glyph, «Нет доступа». No comment count. The card preview source is not specified by the API contract: derive it from verified fields and fall back to a placeholder.
- **Подписки:** 3-column AuthorCard grid (avatar, blog title, owner name), initial focus on the first tile, ids `subs/tile/<blogUrl>`. Empty: «Подписок пока нет» + explanation, no CTA, focus stays on the sidebar. **Contradiction:** the epic says show «Показаны первые 30» when exactly 30 are returned; EXPERIENCE/focus-map say when there are more than 30 (overriding the design's «28 из 55»). E2 returns `total`, so the note can key on `total > 30`; resolve in Story 3.2. The note is not focusable.
- **Автор:** header (avatar, title, owner name) + 4-column post grid, initial focus on the first post (no live card in this epic), ids `author/<blogUrl>/post/<postId>`. Empty: «Публикаций нет». Back pops to the origin.
- **Пост:** two independently scrolling columns. Left: author (OK → Author), title (max 6 lines), date and a read-only, non-focusable like count. Right: blocks. Text renders as plain paragraphs (styles/emoji in Epic 6); image, link, file, external video, audio, poll and unknown blocks show a neutral, non-focusable placeholder. Block focus ids `post/<postId>/block/<blockKey>`, where `<blockKey>` = `<type>:<id>` if the block has an id, else `<type>@<index>`.
- **MediaRow:** thumbnail, «Видео N», title, status; id `post/<postId>/video/<videoId>`; focusable for reading, no «Смотреть» while the player flag is off. Initial focus for a post without the player is not specified (focus-map assumes the primary button); locked post → the author.
- **Locked copy:** «Нет доступа. Этот пост доступен подписчикам уровня «…». Оформить подписку можно на сайте или в приложении Boosty.» No price, no button; teaser shown.
- **Restoration:** before navigating forward, save `{focusId, scrollOffset}` in FocusRestoration (route key + section); on return restore scroll, scroll the item into view by its current index, then focus it. Fallback: neighbor by index → first item of the zone → nearest action above. Refetch, pagination and image loading never move focus. Android post-pop fallback focus is never relied on.
- Every focusable element has a Russian accessibility label (e.g. «Видео. {title}. {author}, {date}.»); copy comes from the typed `ru` catalog; tokens only from `shared/ui/tokens.ts`.

## Cross-Story Dependencies

- 3.1 lands TanStack Query, `queryKeys`, the Post entity (schema, mapper, `Block` union incl. `Unknown`), and PostCard; 3.3 and 3.6 reuse PostCard and the Post entity. 3.2 adds the Author entity and AuthorCard and enables `subs`; 3.3 opens from 3.2 tiles and from the post's author (3.4). 3.4 builds the Post route and block rendering that 3.5 (MediaRows, `MediaRef`) and 3.6 (locked rendering) extend.
- Upstream: Epic 2's `session`, `HttpClient`, error taxonomy, `AccountScope`, FocusRestoration, Shell and screen wrapper.
- Downstream: Epic 4 adds the primary «Смотреть/Продолжить», «С начала», card progress and the Continue row on top of MediaRow/`MediaRef`; Epic 5 adds refresh, filters, search and «Мой блог» to these screens; Epic 6 replaces the block placeholders; Epic 7 adds the Author live card.
