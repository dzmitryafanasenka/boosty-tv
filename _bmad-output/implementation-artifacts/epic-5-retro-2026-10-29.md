### Process lessons (from the story specs and this session)

- **Live checks paid for themselves:** three API surprises were caught before any UI was built — E4 ignores `only_bought`, E7 ignores access params, E5 intersects `tags_ids` — and each became an owner decision instead of a shipped bug (`spec-5-5`, `spec-5-7` Implementation Notes).
- **A fix to a shared pattern landed in one screen only (F1):** the 5.7 review patched the outcome machinery on Автор without checking its sibling on Поиск. Lesson: when a review patches a pattern copied from another screen, grep the copies in the same patch, or extract the pattern first.
- **Spec size:** specs 5.4–5.7 ran at 2400–2800 tokens against a 1600 target; the owner kept them whole each time and the stories still landed, with review loops of 14–20 findings each.
- **Device lessons repeated:** the TV `VirtualizedList` collapses inside an unstyled `TVFocusGuideView` (Stories 5.5 tag list and 5.6 result guide); a stray adb OK opened a player twice in the epic (Story 5.4 incident, Story 5.7). The `docs/testing.md` rule «send OK only after reading the focused element» did not hold in 5.7.
- **Host flake:** an occasional jest worker SIGSEGV drops one suite from a run (Stories 5.6, 5.7; `deferred-work.md`).
- **Session logs** exist only for Stories 5.6–5.7, so process analysis for 5.1–5.5 is narrowed to their specs.
