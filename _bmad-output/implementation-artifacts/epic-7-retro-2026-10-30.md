### Process lessons (from the specs and the session log)

- **Reference-only shapes stayed unverified.** No subscribed blog streamed during the epic, so every E15 probe returned 204. As a result, the E15 200 body, `ok_stream`, E16, E17 and a live `video_stream_start` rest on BoostBuddy code, synthetic fixtures and the demo. Every story said so explicitly. The probes still paid off: 7.5's probe confirmed E18 and justified turning the flag on.
- **Every review pass found cache races in optimistic or polled code:**
  - 7.1: head-follow, background polling, the stale mount cache, card loss after unmount;
  - 7.4: a poll undoing a like, a stream id switch;
  - this retro: F1, structural sharing.
  - All come from TanStack details (cancel ordering, structural sharing, `isFetchedAfterMount`). Lesson: put a mutation/poll helper with these rules in one place (A2), and test each new optimistic path against an equal and a newer poll.
- **Some leak checks were vacuous:** the fixture URLs had no `?sig=` (7.2), and an account test ran on a cleared cache (7.4). Reviews caught both.
- **A device slip:** in 7.4 a key batch went to the Google TV launcher and two OKs landed there (the owner checked the TV: nothing changed). The foreground check is now in the agent memory and briefs, but not in `docs/testing.md` (A6).
- **A host flake:** 1 failed run in 110 of the 7.5 touched suites, never captured (`docs/testing.md` Story 7.5).
- **Spec size:** specs ran at 2300–2800 tokens against the 1600 target; the owner kept every one whole. The review loops still found 6–16 findings per story.
