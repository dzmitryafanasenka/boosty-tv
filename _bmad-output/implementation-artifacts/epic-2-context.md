# Epic 2 Context: Sign in once and stay signed in (P1)

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

The family signs in once on the TV with a phone number and a one-time code, stays signed in across restarts, reboots and token expiry, and lands in a remote-only shell with a sidebar, predictable Back and restored focus. They can sign out safely or re-login quickly when the session truly expires, and a different account never sees the previous account's data. The epic also lays the shared foundations every later epic builds on: design tokens and focus primitives, i18n, `SessionManager`, `AccountScope`, the error taxonomy and retry policy, `Logger`, `FixtureTransport` and the shared screen wrapper. The owner gave the go for Epic 2 on 2026-10-26 after the Epic 1 spike. **Where the newer long-term docs (`docs/focus-map.md`, `docs/testing.md` spike report, `docs/api-contract.md`, ADRs 0006–0008) contradict older planning text (epics, PRD, UX, spine), the newer docs win**; the overrides are called out below.

## Stories

- Story 2.1: Welcome screen on the design foundation
- Story 2.2: Request a sign-in code by phone
- Story 2.3: Confirm the code and create the session
- Story 2.4: The app shell — sidebar, Back and focus
- Story 2.5: Stay signed in across restarts and expiry
- Story 2.6: Session expired and quick re-login
- Story 2.7: Minimal Settings and sign-out
- Story 2.8: Account switch never leaks data

## Requirements & Constraints

- **Sign-in:** phone (editable country code, default `+7`, any E.164 country code) + one-time code via Boosty phone auth. Validate by E.164 rules, not a fixed digit count: accept at least 8 digits including the country code and trim whitespace before `+` (the spike's validator wrongly rejected short valid numbers). Resend becomes available after a 60 s client countdown; «Изменить номер» returns with the number kept. Sign-in completes only after `GET /v1/user/current` (E1) succeeds; if E1 fails after confirm, discard the tokens.
- **Verified auth error shapes only:** wrong code = 400 `invalid_sms_code`; send/resend rate limit = 429 `sms_gate_ratelimit`, which can also hit the **first** send and blocks for roughly 2 h with no wait time given. Show «Слишком много попыток. Попробуйте позже» with no countdown and no auto-retry. Expired challenge, confirm attempt limit and captcha are unverified: map them only if a shape is observed, otherwise `Unknown` with generic copy. Captcha detection only on non-2xx auth responses, never by scanning success bodies. An unpassable captcha is a release blocker.
- **Live facts:** tokens are 64-char opaque strings (not JWTs); `expires_in` = 2592000 (read as seconds); send `expiresIn` units unknown. Fixtures must mirror these live shapes (`sentTransport: "gate"`, `expiresIn: 604800`).
- **Never log or persist** the challenge or code. The phone is stored only in secure storage (prefill for re-login) and wiped on sign-out/account switch. Tokens only in secure storage.
- **Session lifetime:** survives kill, cold start and reboot. Refresh is single-flight: proactive when < 300 s remain, once after a 401 with one retry of the original request.
- **Expiry signal (newer than the spine's "a 4xx"):** only refresh **HTTP 400 with `error: "invalid_grant"`** means `expired`. Any other 4xx, 5xx, 429, timeout or transport error keeps the tokens and stays `signedIn`. Never match on `error_description`.
- **Invalid tokens look anonymous on content endpoints (new):** content calls with a bad/expired token return 200 with `hasAccess=false`, not 401, so refresh never fires from them. Validate the session with E1 at app start and on resume before trusting locked content.
- **Refresh coordinator (binding):** timeouts via `AbortController` on every request; refresh tokens rotate and are single-use, so persist the new pair to SecureStore *before* adopting it and surface save failures; an unparseable 200 or lost response means the token may be burned — keep state, expect `invalid_grant` next, no loop; a session generation guards signOut/reload against in-flight refresh (a late rejection never turns `signedOut` into `expired`); accept `expires_in` only if finite and > 300 s; always send the install's own `device_id`. Tests must cover staggered late 401s, signOut during refresh, save failure on adopt and `expires_in` edge values.
- **Sign-out:** confirm dialog with «Отмена» as default focus; local-only (no server revoke); clear SecureStore first, then memory; then Welcome.
- **Offline cold start with a stored session:** show the offline StateView with «Повторить», never «Сессия истекла».
- **Account isolation:** a different `E1.id` resets all account-scoped data before the new phone and id are written; late async writes from the old account are dropped. Same account keeps everything. Not yet tested with a second real account — Story 2.8 owns it.
- **Verification:** every P1 requirement on the physical Chromecast with Google TV 4K (Android TV 14, 32-bit `armeabi-v7a`, ~350 MB free; build with `-PreactNativeArchitectures=armeabi-v7a`). Label adb-injected vs owner/physical-remote results; never report mocks as device results. Sign-ins spend the server rate limit — do not drop the owner's session without need.

## Technical Decisions

- **Two API request profiles (ADR 0008), chosen by client, never per call site:** `AuthApiClient` (send, confirm, refresh): desktop Chrome UA, `X-App: web`, `X-Locale: ru_RU`, `Referer`/`Origin` boosty.to, `Accept`, `X-From-Id: <device_id>`, form-encoded, no `Authorization`. `HttpClient` (everything else, **including E1**): mobile Android Chrome UA, `Accept`, `Authorization: Bearer`; no web headers, no `X-From-Id`. UA strings are constants in one `shared/api` module. Non-`api.boosty.to` hosts never get Boosty headers or `Authorization`. E1 with the content profile is unproven: Story 2.3 must check it on the device and record the result in `docs/api-contract.md`. Unit tests assert exact header sets per client.
- **SessionManager** (`shared/api`) is the only token reader/writer; UI sees only `signedOut | signedIn | expired`. No tokens in Zustand or UI state.
- **SecureStore** = react-native-keychain 10.0.0 (`KeystoreAESGCM_NoAuth`) behind the port, plus the native reset helper (ADR 0006, gate passed). Classification: `CorruptionException` → delete `RN_KEYCHAIN.preferences_pb` (and a leftover `.tmp`), check `delete()`'s result, reset, `signedOut` with «Войдите снова»; `CryptoFailedException`/`KeyPermanentlyInvalidatedException` → reset, `signedOut`; anything else → keep data, recoverable error, one retry, no sign-out. Keep only data that may be lost together (tokens, phone) in the keychain. Pin the library; re-run the gate on updates.
- **AccountScope:** eager registration in `app/bootstrap.ts` (a test fails on an unregistered account-scoped store); `reset()` is the only cleanup path and bumps a generation that async writes capture. Account-scoped: query cache, Continue history, filters, phone, account id, diagnostics buffer. Device-scoped: `device_id` (UUIDv4, created once per install, survives logout), preferred quality/speed.
- **Errors:** `AppError.kind` (SessionExpired, NoAccess, MediaUrlExpired, NotFound, RateLimited, Client, Server, Network, Parse) and `AuthError.kind` (InvalidPhone, WrongCode, CodeExpired, TooManyAttempts, VerificationRequired, Unknown), built only in `shared/api`, mapped only from verified shapes. Screens pick state/copy by kind (`error.<kind>`), never by status. A 403 is never session expiry.
- **Retries:** GET Network ≤ 2 with backoff, Server ≤ 1, others none; mutations never retried. Guard non-idempotent auth requests (send, confirm) with an in-flight ref, not React state, so held/repeated remote keys cannot double-fire.
- **Navigation (ADR 0007 overrides "native-stack" in the epics text):** root is `@react-navigation/stack` with `detachInactiveScreens={false}`, `headerShown: false`, `gestureEnabled: false`; react-native-screens stays only as a peer and is never rendered; no `RNScreensFragmentFactory` in production `MainActivity`; react-native-gesture-handler 3.4.x with gestures off. Shell swaps sections in place (not stack entries); one modal host for all overlays; typed id-only routes in `app/routes.ts`; sections gated by `app/phaseFlags.ts` (Epic 2: Главная and Настройки only).
- **Shared screen wrapper (`shared/focus`):** every stack screen is wrapped in a `TVFocusGuideView` trapping all four directions (covered screens stay mounted and otherwise receive D-pad focus), and restores focus explicitly — Android's post-pop fallback focus is never relied on.
- **Logger:** redacts tokens, cookies, Authorization, phone, codes/challenge, signed URLs and `signedQuery`; in-memory ring + capped internal file; account-scoped; adb-only export.
- **FixtureTransport** replaces only `HttpClient`'s network layer; serves demo mode (debug-only, persistent «ДЕМО» badge) and integration tests; release build fails if the flag is on; no other HTTP mocking library.
- **Conventions:** tokens from DESIGN.md in `shared/ui/tokens.ts` (no raw colors/sizes); typed `ru` catalog with a hand-written plural selector (no `Intl.PluralRules` in Hermes); no literal strings in components; Golos Text bundled. Tests: Jest + RNTL 14 / test-renderer — re-evaluate the `react-reconciler` 0.33.0 override when RNTL is added. Zod 4 needs `@babel/plugin-transform-export-namespace-from`; once Zod is a production dependency, add a Metro release-bundle check to CI.

## UX & Interaction Patterns

- Remote only; native focus; no JS focus engine and no raw D-pad handlers in this epic. One visible focus target; focus scale via `transform` (no reflow, ring not clipped); pressed scale 0.98; disabled is not focusable; «reduce motion» keeps scale, drops animation. Busy buttons show a spinner, keep focus and ignore repeated OK.
- **Sign-in focus (normative `docs/focus-map.md`, which overrides the design map):** A1 → «Войти в Boosty», Back exits. A2 → the **number** field (← reaches the country code). A2 opened from A11 with the phone prefilled → «Получить код». After IME «Готово»: «Получить код» if valid, else the field. A5 → code field; the resend button is unfocusable during the countdown. A7 wrong code → field cleared and focused; A8 expired → «Выслать новый код»; A9 → «Изменить номер»; A10 → «Попробовать снова» (one send retry only); A11 → «Войти снова», Back exits. Back on code screens → A2 with the number kept.
- **System keyboard:** OK on a field opens the system IME; arrows are not intercepted while it is open; Back closes the keyboard first and focus stays on the field.
- **Shell:** sidebar always expanded; current section (accent bar) distinct from focus; sections open on OK only. ← from the first content column → current sidebar item; → returns to that section's remembered content focus. Back order: modal host (keyboard, dialog, sheet) → stack → in Shell content → sidebar → Главная → exit. No wrap-around at edges. Until Epic 3, Главная shows a neutral «Лента появится здесь» StateView with no action.
- **Focus identity and restoration:** ids `<screen>/<zone>/<id>` with stable content ids (e.g. `auth/phone/number`, `nav/home`, `dialog/signout/cancel`). FocusRestoration is the single store of `{focusId, scrollOffset}` per route key + section; restore scroll, scroll a virtualized item into view by its current index, then focus it; fallback chain: neighbor by index → first item of the zone → nearest action above. Refetch/background updates never move focus. Restoration on a long virtualized list must be proven on the device in Story 2.4.
- **Safe area:** apply the DESIGN.md safe area (48/27 dp) in the shell and decide `edgeToEdgeEnabled` for TV on the device in Story 2.4.
- **Session expired mid-session:** A11 replaces the stack from any screen; after same-account re-login → Главная with saved focus state; different account → fresh Главная.
- **Settings (P1 part):** version + «Выйти из аккаунта»; dialog opens with focus on «Отмена»; cancel returns focus to the row; confirm → A1 with its initial focus.
- Every focusable element has a Russian accessibility label; copy follows EXPERIENCE voice and tone.

## Cross-Story Dependencies

- 2.1 delivers tokens, `FocusableSurface`/`Button`, i18n and the shared screen wrapper used by all later UI. 2.2 → 2.3 (code screen needs the send flow and `AuthApiClient`). 2.3 provides a temporary signed-in screen that 2.4's Shell replaces. 2.5 builds `HttpClient`, the refresh coordinator, the error taxonomy and `FixtureTransport` that 2.6–2.8 test against. 2.6 depends on 2.5's `expired` status and 2.2's prefilled A2. 2.7 introduces `AccountScope.reset()` and bootstrap registration; 2.8 extends it to account switch.
- Downstream: Epic 3 replaces the Главная placeholder and first sends feed/subscription calls with the content profile (Stories 3.1, 3.2 verify them on the device); Epic 4 relies on the content profile for E8/E9 playback and progress; `SET` diagnostics and the system-player setting (Epic 8) extend Story 2.7's Настройки.
