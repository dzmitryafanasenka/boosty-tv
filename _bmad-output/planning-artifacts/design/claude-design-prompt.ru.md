# Промт для Claude Design (v2, по итогам аудита 2026-10-25)

Приложить к запросу: `docs/feature-parity.md`, `docs/api-contract.md`, бриф `_bmad-output/planning-artifacts/briefs/brief-boosty-tv-2026-10-25/brief.md`.

Рекомендуемый порядок — два захода:
- **Заход 1:** дизайн-система, ключевые компоненты с фокус-состояниями, плеер, главная, пост.
- **Заход 2:** остальные экраны, состояния, прототип и handoff.

Ниже — полный текст промта для обоих заходов. В первом заходе ограничьте объём фразой «Сейчас сделай только пункты A, B, C».

---

Ты — senior product designer, специализирующийся на TV-интерфейсах и управлении пультом. Спроектируй цельный high-fidelity дизайн и интерактивный прототип **Boosty TV**. Это неофициальный клиент Boosty для телевизора, название рабочее и не утверждено как бренд. Приложение не является официальным продуктом Boosty и не копирует его фирменный стиль.

## 1. Контекст

- **Для кого.** Одна семья, один общий аккаунт Boosty, одна приставка Chromecast with Google TV 4K. Владелец технически подкован, остальные члены семьи — нет: им нужно «включил — смотришь».
- **Главная работа.** Смотреть видео из своих подписок с дивана. Всё остальное обязательно, но вторично.
- **Почему не BoostBuddy.** Это единственный существующий кастомный клиент. Он функциональный референс, но **не визуальный**. С ним две проблемы: неудобная навигация пультом и регулярные вылеты из аккаунта. Наш дизайн должен решать обе.
- **Платформа.** Android TV / Google TV, реализация на React Native + react-native-tvos. Apple TV (tvOS) is out of scope (owner decision 2026-10-27).
- **Прототип.** Любой HTML/React DOM-прототип — только иллюстрация дизайна, а не production-код. Браузерный фокус не доказывает поведение нативного фокуса Android TV.

## 2. Источник истины о возможностях

Используй приложенные `feature-parity.md` (там ID возможностей и решения владельца в §12) и `api-contract.md`. Ссылайся на ID в спецификации экранов, например `PLAY-02`. Не добавляй ничего, чего там нет, кроме явных пометок «улучшение клиента».

**В объёме:**

| Область | Что есть | Важные детали |
|---|---|---|
| Вход | Телефон → код (SMS, мессенджер или приложение Boosty) | Ввод с пульта через системную клавиатуру ТВ. Повторная отправка доступна через 60 с. «Изменить номер». Сессия живёт неделями, повторный вход — редкое исключение. |
| Подписки | Список авторов (аватар, название блога, имя автора) + «Мой блог», если у пользователя есть свой блог | Список может быть длинным. Пагинация API не подтверждена. Не смешивать с оформлением платной подписки. |
| Лента | Посты подписок, курсорная подгрузка | Фильтры и поиск применяются к ленте |
| Автор | Шапка (аватар, название, имя), посты, поиск по автору, фильтры, карточка эфира | **Описание и обложка автора в API не подтверждены.** Проектируй без них или как условный элемент. |
| Поиск | Две области: **по ленте подписок** и **внутри автора** | Глобального поиска по Boosty нет. Подписывай область поиска. |
| Фильтры | Доступ: «Доступные мне» (по умолчанию), «Все посты», «Только купленные». Период (диапазон дат). Теги (мультивыбор) | Применяются сразу, кнопки «Применить» нет. Есть «Сбросить». **Сортировки нет**, её не проектируй. Выбор периода нужен в TV-виде, а не как веб-календарь. |
| Контент поста | Форматированный текст (жирный, курсив, подчёркнутый, ссылки, эмодзи), изображения, **несколько видео**, аудио, файлы, внешние видео (YouTube и т.п.), опрос, счётчик лайков (только просмотр) | Ссылки, файлы и внешние видео открываются **QR-кодом «Открыть на телефоне»**. Неизвестные блоки показываются аккуратной заглушкой. |
| Закрытый пост | Показывается тизер и состояние «нет доступа» | Без кнопок оплаты и без ложного обещания доступа |
| Опросы | Один вариант: выбор сразу отправляет голос, повторный выбор отзывает его. Несколько вариантов: отметить → «Проголосовать». «Отозвать голос». Завершённый опрос. Результаты (проценты, число голосов) видны всегда. | Нужны состояния отправки и ошибки. В BoostBuddy ошибка молча игнорируется, у нас так быть не должно. Для одиночного выбора предложи защиту от случайного OK и отметь её как дизайн-решение. |
| Видеоплеер | Play/pause, перемотка стрелками (шаг 5 с, ускорение при удержании), таймлайн, прошедшее и общее время, медиаклавиши, Menu/Info открывает настройки, качество, скорость 0.5–3× | Подробности — в разделе 4 |
| Прямые эфиры | Карточка эфира на странице автора: «идёт» или «запланирован», зрители, лайки, требуемый уровень подписки. Плеер эфира: бейдж LIVE, время с начала, **без перемотки**, скорость 1×, состояние «Стрим завершён». Лайк эфира. «Поделиться» через QR. | Эфиры подтверждены аудитом, проектируй их |
| События | Список событий, например «стрим начался» | Улучшение клиента: в BoostBuddy этот список не выведен в интерфейс. Формат ответа API пока не проверен, поэтому раздел условный. Предложи место в навигации. |
| Настройки | Выход с подтверждением. «Системный видеоплеер» (открывать видео во внешнем Android-плеере). Версия приложения. Диагностика: сбор логов для тестирования, скрытый или технический раздел. | Темы нет, только тёмная. Нет скачивания, нет обновления внутри приложения, нет тарифов и телеметрии. |

**Вне объёма — не рисовать:**
- комментарии, ответы и счётчики комментариев;
- скачивание видео;
- светлая тема;
- профили и несколько аккаунтов;
- донаты, оплата и оформление подписки;
- QR-вход и вход с телефона-компаньона;
- рекомендации, главы, субтитры, аудиодорожки, превью кадров при перемотке;
- автоплей на главной, огромный hero;
- синхронизация «продолжить просмотр» как облачная функция;
- глобальный поиск;
- чат эфира.

**Про прогресс и длительность — честно:**
- Позиция просмотра хранится на сервере Boosty **отдельно для каждого видео**. Она приходит вместе с постом, и «Продолжить» внутри поста реально.
- **Отдельного API со списком «начатых» видео нет.** Ряд «Продолжить просмотр» на главной — улучшение клиента: локальная история на устройстве плюс серверная позиция. Помечай его так.
- **Длительность видео в ответе API не подтверждена.** Покажи карточку в двух вариантах: с длительностью и полосой прогресса, и без них. Полоса прогресса без длительности невозможна.

## 3. Визуальное направление

- Один согласованный и проработанный вариант, а не несколько поверхностных концепций.
- Тёмный графитовый фон, спокойные поверхности, сдержанный тёплый оранжевый акцент. Независимый бренд.
- Читаемость с 2–3 метров, крупная русская типографика, длинные названия не ломают сетку.
- Карточки 16:9, узнаваемые аватары авторов.
- Базовый кадр 1920×1080. Адаптацию ключевого экрана (главная) покажи на 1280×720. Размеры — дизайн-координаты, а не RN units.
- Safe area около 5% — это стартовая гипотеза. Обоснуй её композицией.
- Боковая навигация с подписями. Режимы compact/expanded вводи, только если они не усложняют фокус.
- Без стекла, кислотных градиентов, мелких кнопок и декоративных графиков.
- Данные вымышленные, русские и согласованные между экранами:
  - 6–8 авторов;
  - посты разных типов: видео, несколько видео в одном посте, аудио, текст с картинками, опрос, закрытый пост, файл, эфир;
  - длинные заголовки;
  - правдоподобные даты.

## 4. Экраны и состояния

**A. Вход и сессия**
1. Welcome с действием «Войти в Boosty».
2. Ввод номера телефона: фокус на поле, системная клавиатура ТВ, ошибка «Некорректный номер».
3. Ввод кода: подсказка, куда мог прийти код; таймер «Повторная отправка через N с»; «Выслать повторно»; «Изменить номер»; состояния неверного кода, истёкшего кода и слишком частых попыток.
4. Блокирующее состояние «Boosty требует дополнительную проверку» (капча). Это потенциальный блокер, его нужно показать честно, без обходных путей.
5. «Сессия истекла» и повторный вход.

**B. Главная (лента)**
- Ряд «Продолжить просмотр» как улучшение клиента, затем свежие публикации подписок.
- Карточки различают тип: видео (одно или несколько), аудио, текст/изображение, опрос, закрытый пост, эфир.
- На карточке: превью, заголовок, автор, дата, длительность и прогресс (если есть), отметка доступа. Без лишних метаданных.
- Подгрузка при прокрутке и ошибка подгрузки в конце списка с «Повторить».

**C. Подписки** — сетка или список авторов, «Мой блог», «Нет подписок», длинный список (50+).

**D. Автор** — шапка, карточка эфира («идёт», «запланирован», «нужен уровень подписки»), посты, поиск внутри автора, панель фильтров (доступ, период, теги). Видимые активные фильтры, их количество, «Сбросить».

**E. Поиск** — подпись области («по подпискам»), поле, системная клавиатура, восстановление фокуса после её закрытия, результаты, загрузка, «Ничего не найдено», ошибка.

**F. Пост**
- Заголовок, автор, дата, читаемый текст с раскрытием длинного текста.
- Основное действие: «Смотреть» или «Продолжить»; вторичное: «С начала» (улучшение клиента).
- Несколько видео или аудио в посте: выбор конкретного медиа с отдельным прогрессом у каждого.
- Изображения, QR-диалог для файла, ссылки и внешнего видео.
- Заглушка неподдерживаемого блока. Закрытый пост.

**G. Видеоплеер** — самый важный экран.
- Состояния: без оверлея, оверлей, пауза, буферизация, перемотка с визуальным подтверждением новой позиции, ошибка.
- В оверлее: название поста и видео, **автор** (улучшение клиента), play/pause, таймлайн, прошедшее и оставшееся время.
- Панель настроек со своим фокусом и возвратом на кнопку-инициатор:
  - **Качество** — только реально доступные варианты. Адаптивный поток (HLS/DASH) показывать как «Авто», ручные варианты — 2160p…144p.
  - **Скорость** — пресеты 0.5, 0.75, 1, 1.25, 1.5, 1.75, 2, 3×. Только для записи, не для эфира.
- Истёкшая ссылка на видео: ненавязчивое «Восстанавливаем воспроизведение…», одна автоматическая попытка. Если не вышло — «Не удалось воспроизвести видео» с кнопками «Повторить» и «Назад».
- Плеер эфира: LIVE, время с начала, без таймлайна перемотки, «Стрим завершён».
- Back: закрыть панель → скрыть оверлей → выйти из плеера с восстановлением карточки и прокрутки.
- Оверлей не скрывается автоматически во время работы с настройками, перемотки, паузы и ошибки.

**H. Аудио** — компактный встроенный плеер в посте: play/pause, прогресс и позиция/длительность, перемотка. Одновременно играет только один трек. Без очереди и мини-плеера между экранами. Позиция аудио не сохраняется.

**I. Опросы** — все состояния из таблицы в разделе 2: выбор, отправка, успех, ошибка, уже голосовал, завершён, один и несколько вариантов, «Отозвать голос».

**J. События** — список, пустое состояние, ошибка. Раздел условный.

**K. Настройки** — выход с модальным подтверждением и возвратом фокуса после отмены, «Системный видеоплеер», версия, диагностика.

**L. Системные состояния** — skeleton, пусто, нет подписок, ничего не найдено, ошибка сети, нет доступа, сессия истекла, неподдерживаемое медиа. У каждого состояния есть понятное действие и определённый начальный фокус.

## 5. Фокус и управление — обязательная часть

Дизайн без фокус-состояний не считается готовым.

- Управление: стрелки, OK, Back, медиаклавиши. На каждом ключевом макете виден текущий фокус.
- Различай состояния focused, selected/current, pressed, disabled. Текущий раздел навигации и текущий фокус — разные вещи.
- Фокус обозначается не только цветом: контур или поверхность плюс мягкое масштабирование без сдвига соседей и без обрезания.
- Обязательные компоненты со всеми состояниями: VideoCard, PostCard (по типам), AuthorCard, LiveCard, NavItem, PrimaryButton, FilterChip, SettingRow, PollOption, PlayerControl, QualityOption, TextField (телефон и код), QrDialog.
- Карта переходов: sidebar ↔ content ↔ filters ↔ grid ↔ dialogs.
  - Модальное окно изолирует фокус, при закрытии фокус возвращается к инициатору.
  - Без неожиданного wrap-around.
  - Для крайних карточек и исчезнувшего элемента нужен fallback.
- Восстановление карточки и прокрутки после поста и плеера обязательно. Подгрузка и обновление списка не сбрасывают фокус.
- Анимации — токены (длительность и easing): короткие и функциональные.

## 6. Интерактивный прототип: сценарии

1. Welcome → телефон → код → главная.
2. Главная → Подписки → Автор → Пост с двумя видео → Видео 2 → Качество → Back до исходной карточки.
3. «Продолжить просмотр» → перемотка → выход → прогресс виден на карточке и в посте.
4. Поиск по подпискам → результат → пост → возврат к запросу и результату.
5. Автор → фильтр «Только купленные» + тег → сброс.
6. Пост с опросом (один вариант и несколько) → отправка → результат → отзыв голоса.
7. Автор с идущим эфиром → плеер эфира → «Стрим завершён».
8. Пост с файлом → QR-диалог → закрытие с возвратом фокуса.
9. Ошибка сети → повтор. Закрытый пост → объяснение. Выход → отмена с возвратом фокуса.

Клавиатура в прототипе эмулирует пульт. Обработка стрелок отделена от ввода текста. Если интерактивность недоступна, дай аннотированные storyboard-переходы и явно отметь это ограничение.

## 7. Что выдать (в таком порядке приоритета)

1. Токены: цвета, типографика, отступы, размеры и радиусы, focus ring и scale, motion. **Также в виде markdown-таблицы.**
2. Библиотека компонентов с матрицей состояний.
3. High-fidelity экраны из раздела 4 и адаптация на 1280×720.
4. Таблица фокуса: экран | начальный фокус | ↑↓←→ | OK | Back | восстановление. Также в markdown.
5. Прототип или storyboard.
6. Handoff для RN TV: компоненты, layout constraints, допущения о виртуализации списков, focus ID, поведение оверлеев. Без CSS под видом RN-кода.
7. Отдельный список допущений и условных элементов со ссылкой на ID из feature-parity (например, «Продолжить просмотр», длительность на карточке, события, описание автора).

**Приоритет:** предсказуемое управление пультом и удобный плеер > читаемость > быстрый доступ к подпискам > визуальная эффектность.
